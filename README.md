# docx-helper - 文档排版助手

> 对已有的 Word 文档一键套用规范排版 —— 分析诊断、对话确认、版本化输出，原文件永不覆盖。

## 它能做什么

`docx-helper` 是一个 AI Skill + 命令行工具，按规范排版规则（`references/rules.md`，依据 GB/T 9704-2012 及实际使用习惯）自动调整 Word 文档格式。一句话说：**把你在 Word 里反复手动调的页边距、字体、行距、页码，全部自动搞定。**

排版后你的文档长这样：A4 纸、方正小标宋二号大标题、黑体/楷体/仿宋分层级标题、仿宋三号正文固定行距 28.9 磅、首行缩进两字符、"— N —" 格式页码（奇数右下、偶数左下）。

它不直接改你的原文件，每次排版都输出一个带版本号的新文件，随时可以回退。

### 核心功能

- **页面设置**：A4 纸张、标准页边距（上 3.7 / 下 3.5 / 左右 2.7 cm）、页脚距底 2.54cm
- **字体切换**：自动为标题/正文换上对应的方正字库（方正小标宋/黑体/楷体/仿宋）
- **标题识别**：按语义深度判定章/节/子节/条目/落款/图题/正文（不看编号字形）
- **版本化输出**：每次排版输出 `原名+docx-helper+v{N}.docx`，永不覆盖原文件
- **内容质检**：`--check-content` 自动扫描错别字、叠词、编号重复/跳号（支持（1）/1./一、 三种格式）
- **图片修复**：`--fix-images` 浮动图片转嵌入，消除图文错位（正文+表格内图片均覆盖）
- **模板建文档**：`--new` 从内置规范模板创建新文档（格式全对，零排版）
- **落款对齐**：巡检日期/签名等落款行左对齐+固定左缩进，多行首字严格对齐
- **双层校验**：AI 过程复核（结构误判/内容误伤/位置异常）+ 用户最终验收（打开 Word 确认渲染）

## 快速开始

安装完成后，在 WorkBuddy 中有两种调用方式：

**方式一：斜杠命令（最直接）**

```
/docx-helper 检查这份文档的格式
```

**方式二：自然语言**

把 `.docx` 文件拖进对话框，直接说：

> 帮我把这份报告排版

AI 会先**重置**文档的所有手动格式，再**通读全文判断结构**——哪些是章标题（chapter）、哪些是节标题（section）、哪些是条目（item）——然后把结构方案列给你确认，确认后输出 `报告+docx-helper+v1.docx`。全程不用打开 Word。

### 也支持命令行

```
# 1. 重置：清空所有手动格式，得到中性文档
python scripts/format.py --reset 报告.docx

# 2. 列出段落（可选，便于判结构）
python scripts/format.py --list 报告+reset.docx

# 3. 按结构映射套用排版
python scripts/format.py --apply 报告+reset.docx --structure structure.json

# 其他命令
python scripts/format.py --analyze 报告.docx        # 格式差分分析（只读）
python scripts/format.py --check-content 报告.docx  # 内容质检（错别字/编号）
python scripts/format.py --fix-images 报告.docx      # 图片错位修复
python scripts/format.py --new --title "重保方案" --output 新文档.docx  # 模板建文档
```

## 安装

在 WorkBuddy 中输入下面这句话，AI 会自动读取 GitHub 仓库内容并完成安装：

```
请阅读并安装这个skill：https://github.com/hunyed15/docx-helper
```

AI 会自动处理 SKILL 加载、`python-docx` 依赖安装等所有步骤。

> **前置条件**：使用前请确保系统已安装以下四款方正字体，否则排版后的文档在 Word 中打开会提示字体缺失：
>
> - **方正小标宋_GBK** — 用于大标题
> - **方正黑体_GBK** — 用于章标题 (chapter)
> - **方正楷体_GBK** — 用于节标题 (section)
> - **方正仿宋_GBK** — 用于子节标题/条目/正文
>
> Windows：右键字体文件 → "为所有用户安装"；macOS：双击字体文件 → "安装字体"；Linux：放入 `~/.fonts/` 后运行 `fc-cache -fv`。

## 排版规则

完整规则见 `references/rules.md`（唯一规则依据，可执行版为 `docx-helper-default.json`）。

### 页面

| 项目 | 值 |
|------|-----|
| 纸张 | A4 (210 × 297 mm) |
| 上边距 | 3.7 cm |
| 下边距 | 3.5 cm |
| 左/右边距 | 2.7 cm |
| 页脚距底边 | 2.54 cm |

### 字体体系

| 用途 | 字体 | 字号 |
|------|------|------|
| 大标题 (title) | 方正小标宋_GBK | 二号 (22pt) |
| 章标题 (chapter) | 方正黑体_GBK | 三号 (16pt) |
| 节标题 (section) | 方正楷体_GBK | 三号 (16pt) |
| 子节标题 (subsection) | 方正仿宋_GBK | 三号 (16pt) |
| 条目/正文 (item/body) | 方正仿宋_GBK | 三号 (16pt) |
| 页码 | Times New Roman | 四号 (14pt) |

> 所有西文/数字使用 Times New Roman，无加粗，全黑色。

### 段落

| 项目 | 值 |
|------|-----|
| 正文行距 | 28.9 磅（固定值） |
| 正文首行缩进 | 2 字符 |
| 页码 | 奇数右下、偶数左下，格式 — N — |

### 标题识别（按语义深度判定）

GB/T 9704-2012 的四层序数体系（`一、`→`（一）`→`1.`→`（1）`）是常见惯例，但不是唯一写法。判定层级看**语义深度**而非编号字形：

| 结构类型 | 常见编号 | 字体 | 说明 |
|---------|---------|------|------|
| chapter（章）| `一、二、三、` | 黑体 | 文档最顶层分章 |
| section（节）| `1.` `2.1` `（一）` | 楷体 | 章的直属子级，无论写成什么编号 |
| subsection（子节）| `4.1.1` | 仿宋 | 节的直属子级 |
| item（条目）| `（1）` `①②` | 仿宋 | 带括号/圈号的列表项 |
| signature（落款）| 巡检日期/巡检人 | 仿宋 | 左对齐+固定左缩进，首字对齐 |
| caption（图题）| 图 2-1 / 表 2-1 | 黑体 | 居中 |

## 迭代工作流

排版不是一锤子买卖。基于同一份 reset 文档反复迭代：

```
v1: 报告.docx → reset → 判结构 → 确认 → 报告+reset+docx-helper+v1.docx
v2: 微调 structure.json → 报告+reset+docx-helper+v2.docx
```

每次基于同一份 reset 文档继续调整，完整追溯，随时回退。

## 双层校验（重要）

1. **AI 过程复核**：套用后通读成品，检查结构误判（落款排成正文）、内容误伤（编号烘焙异常）、位置异常（图片嵌入）、关键观感
2. **用户最终验收**：AI 看不到 Word 渲染效果（孤行/孤页/图片叠压/落款对齐），最终视觉验收由用户在 Word 中打开确认——agent 交付时会提供"重点确认清单"

## 自定义配置

通过 `.docx-helper.json` 可覆盖任意排版参数（不改的沿用默认）：

```json
{
  "fonts": { "section": "思源宋体", "body": "思源宋体" },
  "sizes": { "body": 14 },
  "typo_rules": { "部署": "布署" }
}
```

> `typo_rules`：`--check-content` 的自定义错别字库，合并到内置库使用。

## 限制与已知问题

- **仅支持 .docx 格式**：旧版 .doc 请先在 Word 中另存为 .docx
- **字体前置条件**：必须安装方正字库，否则打开文档会字体缺失
- **脚本不覆盖的场景**（需手动处理）：版头红色分隔线、发文机关标志、发文字号、签发人、印章、版记、多行标题梯形排列
